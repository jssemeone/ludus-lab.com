Описание асимметричной криптографии +

Асимметричная криптография использует пару ключей: открытый (public) для шифрования данных и закрытый (private) для расшифрования. Эта технология позволяет решить две главные задачи безопасности: обеспечение конфиденциальности и аутентификации данных.

1 Генерация ключевой пары

Каждый участник (Алиса, Боб) генерирует свою пару ключей: открытый и закрытый. Закрытый ключ никогда не передается и хранится в секрете, а открытый можно свободно распространять.

2 Выбор алгоритма асимметричного шифрования

Основные алгоритмы: RSA (широко используется, основан на факторизации больших чисел) и ECC (Эллиптические кривые, более эффективен при меньшей длине ключа).

3 Обмен открытыми ключами через доверенный центр

Для предотвращения атак "man-in-the-middle" открытые ключи должны распространяться через доверенные источники. Обычно используются Удостоверяющие центры (CA), которые подписывают сертификаты, подтверждающие принадлежность открытого ключа определенному лицу.

4 Шифрование и расшифрование

Для обеспечения конфиденциальности: Алиса шифрует сообщение открытым ключом Боба, и только Боб может расшифровать его своим закрытым ключом. Для аутентификации: Алиса подписывает сообщение своим закрытым ключом, и любой может проверить подпись открытым ключом Алисы.

5 Цифровая подпись

Для создания цифровой подписи Алиса вычисляет хеш сообщения и шифрует его своим закрытым ключом. Боб проверяет подпись, расшифровывая её открытым ключом Алисы и сравнивая с хешем полученного сообщения.

6 Протокол Диффи-Хеллмана для обмена ключами

Для гибридных систем (как TLS/SSL) используется протокол Диффи-Хеллмана для безопасного обмена симметричным ключом сессии с помощью асимметричной криптографии.

SSL/TLS сертификаты для веб-безопасности
Защита веб-трафика с помощью SSL/TLS сертификатов для шифрования данных между браузером и сервером.
Рекомендуется: ECC 256-bit (современный стандарт) или RSA 2048-bit (широкая поддержка)
📧
PGP/GPG для электронной почты
Обеспечение конфиденциальности и аутентификации электронных писем с помощью шифрования и цифровых подписей.
Рекомендуется: RSA 3072-bit или ECC 384-bit для баланса безопасности и производительности
💻
Подпись программного обеспечения
Цифровая подпись программного кода для подтверждения его подлинности и целостности при распространении.
Рекомендуется: RSA 4096-bit (максимальная надежность для критически важного ПО)
📄
Электронная подпись документов
Юридически значимая электронная подпись для документов с подтверждением личности подписанта через доверенный центр.
Рекомендуется: GOST Р 34.10-2012 (требуется для юридической силы в РФ)
